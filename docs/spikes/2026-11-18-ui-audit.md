## 2. Existing Visual Language, Design Tokens & Patterns

### 2.1 Design Read & Liveliness Dials (Inferred from Existing App)
> Reading this as: **Self-hosted PaaS / Docker control plane** for server operators and developers, in a **dark obsidian utility-panel** visual language, dial **ENERGY 1 / RHYTHM 1 / MOTION 1**.

- **ENERGY 1 (Calm):** High-density operational tables, forms, and status readouts. No hero marketing gradients, no decorative illustrations.
- **RHYTHM 1 (Uniform):** Consistent `1px` hairline cards (`rounded-xl border border-white/[0.07] bg-[#111115]/90`), uniform form field spacing, predictable header + body + footer dialog rhythm.
- **MOTION 1 (Minimal):** `100-150ms` hover/press state transitions (`transition-colors`, `active:scale-[0.98]`), View Transitions API at `150ms` (`src/index.css:181-192`), `prefers-reduced-motion` honored. No choreography; spin animation reserved for active async tasks (`Loader2`, `RefreshCw`).

Note: `src/styles/solid-glass.css` is imported for `copilot/` chat surfaces only; the rest of the control plane uses explicit dark hex + Tailwind zinc/status utilities. No light/dark toggle exists.

### 3.2 Critical Functional & Anti-Slop Defects Found in `CaddyProxyView.tsx`
1. **Fabricated / Non-Live Config Preview (`R-38` / `C-5` violation):**
   - `CaddyProxyView.tsx:270-360` synthesizes `rootComposeYaml` (`container_name: nextdeploy_caddy`, `CADDY_INGRESS_NETWORKS=nextdeploy_net`) and `liveConfigJson` entirely in client React memory.
   - Meanwhile, `backendApi.caddyOverview()` (`src/lib/api/systemAndTokensApi.ts:46-56`) already calls `GET /caddy/overview` which returns real `root_compose` and `live_config` from the server (`internal/handlers/caddy.go:955-997`), and **is never called anywhere in `src/`**.
   - Under multi-proxy, hardcoded Caddy compose/JSON is actively wrong for Angie (`angie.conf`, `nd-proxy`) and Ferron (`ferron.conf`, `nd-proxy`). Fix: call `GET /api/v1/proxy/overview` (or `/caddy/overview`) and display real server output, with honest loading/error/empty states.

   - `acmeEmail` (`:137`) initializes to `''` and is never hydrated from `caddyInfo?.config?.email`.
   - `caddyImage` (`:138`) hardcodes `'lucaslorentz/caddy-docker-proxy:ci-alpine'` and is never hydrated from `caddyInfo?.config?.caddy_image` (or `proxy_image`).

3. **Hardcoded Settings Engine Text (`UsersAndSettingsView.tsx:1854`):**
   - `"Reverse Proxy Engine"` row displays static text `"Caddy 2 (Caddyfile + Admin API)"` regardless of installed engine.

### 4.1 Shared Types & API Contracts (`src/lib/api/proxyApi.ts` + backward compat)
Keep `caddyApi` methods as aliases in `backendApi` for existing callers while introducing canonical proxy types and `/api/v1/proxy/*` client calls:

```ts
export type ProxyEngineName = 'caddy' | 'angie' | 'ferron';

export interface ProxyCapabilities {
  auto_tls: boolean;
  internal_tls: boolean;
  on_demand_tls: boolean;
  docker_upstream_discovery: boolean;
  php_fastcgi: boolean;
  basic_auth_bcrypt: boolean;
  regex_routing: boolean;
  require_target_file: boolean;       // needed for RuleEditorModal gating
  h2_idle_timeout: boolean;
  write_timeout: boolean;
  read_header_timeout: boolean;       // needed for ProxyOptionsView gating
  read_body_timeout: boolean;
  grace_period: boolean;              // needed for ProxyOptionsView gating
  max_header_size_http1: boolean;     // needed for ProxyOptionsView Ferron caveat
  trusted_strict: boolean;            // needed for ProxyOptionsView gating
  long_streams_on_reload: boolean;
  admin_api: boolean;                 // true for Caddy/Ferron? (Caddy admin_api input)
  experimental: boolean;
}

export interface ProxyLastSwitch {
  from: ProxyEngineName;
  to: ProxyEngineName;
  at: string;                         // RFC3339
  status: 'ok' | 'rolled_back' | 'failed' | 'in_progress';
  error?: string;
}

export interface ProxyPreflightItem {
  capability: string;
  message: string;
  affected_sites?: Array<{
    site_id: string;                  // e.g. "app:12:dom:4", "php:myblog", "route:3"
    label: string;                    // domain or site name
    detail?: string;
  }>;
}

export interface ProxyPreflightResponse {
  ok: boolean;
  target: ProxyEngineName;
  can_switch: boolean;
  requires_experimental_ack: boolean;
  hard_blocks: ProxyPreflightItem[];
  soft_warnings: ProxyPreflightItem[];
  checks: {
    dry_run_ok: boolean;
    dry_run_output?: string;
    ports_free_or_owned: boolean;
    docker_socket_ok: boolean;
  };
  error?: string;
}
```
